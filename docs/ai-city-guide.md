# AI 城市嚮導（3D NPC）規劃

2026-11-07 · 三站導覽已整合，實機驗收中

使用者在城市地圖裡問問題，手機上的模型用白話回答；城市裡的嚮導小人沿著馬路走到相關的大樓，打開那一類的步驟，一站一站帶著辦完。

> 例：「爸爸中風快出院了，我要申請什麼？」→ 嚮導回答三件事要辦，接著走到「傷病與醫療」大樓打開「出院返家照顧」，辦完再帶你去「高齡與長照」、「身心障礙」。

## 1. 先讀：比賽規則對這個功能的限制

出自入門指引第 06 章「AI 使用指引」與競賽須知（115.08.27 版）。

| 規則 | 對我們的影響 |
| --- | --- |
| 執行時的推論必須在手機端完成，不可呼叫雲端 API 或遠端模型 | 模型放在台北通 App 裡跑，網頁只負責送問題、收回答 |
| 評審可能**關閉網路**現場出題 | 模型、網頁、城市模型都要能離線使用，見[第 7 節](#7-斷網-demo)。Demo 前用飛航模式完整測一次 |
| 不可使用危害國家資通安全清單所列的 AI 工具與模型（含大陸廠牌） | Qwen、DeepSeek、GLM、Yi、MiniCPM、InternLM、Baichuan 這類模型都不能用（以官方清單為準）。**換大模型前先確認來源** |
| 套件要開源、免費 | 推論框架用入門指引列的 `flutter_edge_ai`（MIT）或 `llamadart`（MIT） |
| README 要揭露模型名稱、版本、量化格式、推論框架與來源 | 見[第 9 節](#9-繳交前要補的文件) |
| 決選有問答，評審會問設計考量 | AI 產生的程式碼要自己讀過一遍 |

第一支實測手機是隊員自己的 iPhone。先試 **Gemma 4 E4B IT** 通用 LiteRT-LM 量化檔，約 3.66 GB，模型存放於 App 私有空間。用 3D 地圖和模型同時開啟的狀態測試完整流程。E4B 在個別裝置載入失敗時會試已安裝的 **Gemma 4 E2B IT**。沒有可用模型時，仍可用本機搜尋、建議問題和「預設說明」走完三站。[E4B 模型檔](https://huggingface.co/litert-community/gemma-4-E4B-it-litert-lm/tree/main)

這支 iPhone 上，E4B 在 CPU 路徑遇到記憶體配置錯誤。E2B 約 3 秒選出固定情境的三站路線，並完成導覽。因此此機的建置優先使用 E2B，其他手機仍需各自實測。

## 2. 選定情境：爸爸中風，下週出院

只準備一個情境。我們比較了目前有完整步驟的事件，再看哪一組能串起**最多棟大樓**。嚮導要「走到不同建築」，情境只落在一棟大樓的話就沒得走。

| 事件 | 大樓 | 步驟 | 資源 | 台北通服務 | 電話 | AR 地點 |
| --- | --- | --- | --- | --- | --- | --- |
| 申請身心障礙證明 | 身心障礙 | 5 | 9 | 5 | 1 | 3 |
| 家人疑似失智 | 高齡與長照 | 5 | 11 | 4 | 3 | 1 |
| 懷孕到生產 | 懷孕與育兒 | 6 | 9 | 6 | 0 | 1 |
| 出院返家照顧 | 傷病與醫療 | 5 | 9 | 5 | 2 | 0 |
| 申請長照服務 | 高齡與長照 | 4 | 9 | 3 | 2 | 0 |
| 親人過世 | 身後事 | 5 | 7 | 4 | 0 | 1 |

單一事件裡沒有誰特別突出，但「中風出院」可以把三個事件串成一條路線：

| 站 | 大樓（`categoryId`） | 事件（`eventId`） | 步驟 |
| --- | --- | --- | --- |
| 1 | 傷病與醫療（`health`） | 出院返家照顧（`discharge-home`） | 出院準備、借用輔具、回診交通、請假與給付、回到日常 |
| 2 | 高齡與長照（`elder-care`） | 申請長照服務（`long-term-care`） | 申請長照評估、到府評估、擬定照顧計畫、照顧者也要被照顧 |
| 3 | 身心障礙（`disability`） | 申請身心障礙證明（`disability-certificate`） | 到區公所申請、醫院鑑定、需求評估、領取證明、申請福利 |

合計 14 步、27 項資源、13 個台北通服務、5 支電話、3 個 AR 地點，用到七種辦理方式裡的六種（臨櫃、到醫院、電話、在家、等候、線上）。這是目前功能最多的組合，也剛好是使用者舉的例子。故事也接得上計畫書：故事四（黃大哥中風後申請身障證明）加上故事一（照顧者第一次知道喘息服務）。

**情境人物**（虛構）：陳小姐 45 歲，72 歲的爸爸中風住院，下週出院，出院後左側無力、需要輪椅。她要「幫家人辦」。

**待查證**：中風後多久可以做身障鑑定、長照評估能不能在住院時先申請等時間點，回答前要先對照官方資料。目前的步驟內容是示範資料，嚮導回答時也要這樣說明。

## 3. Demo 主流程

1. 打開城市地圖，嚮導小人站在城市前方的人行道上，頭上有「問我」的小提示。
2. 點嚮導小人打開對話框，再點[第 4 節](#4-測試問題)第一個建議問題「爸爸中風快出院了，我要申請什麼？」。點一下就送出。
3. 手機端模型選出候選項後，畫面顯示對應的簡短說明。這個建議問題已綁定三站路線，按「帶我去」即可開始。模型無法回答或選錯時顯示同一路線的「預設說明」。
4. 嚮導先走到「傷病與醫療」，打開「出院返家照顧」。接著按兩次「下一站」，依序到「高齡與長照」和「身心障礙」。每站展示大樓和事件抽屜即可，現場不逐項勾完 14 個步驟。
5. 第三站顯示完成。照顧者支持留在第二站的內容，也可在完成畫面顯示提醒及 1999、1966 按鈕。

對話框也保留打字和麥克風入口。語音輸入通過展示機的離線測試後，可另外展示；固定情境一鍵送出是主流程。正式使用時，打勾的進度仍與清單、地圖共用 `stores/progress`。

問到情境以外的事（例如「我要結婚」），嚮導說明目前只示範中風出院的情境，並建議點「婚姻與家庭」大樓自己看，或撥 1999。

## 4. 測試問題

第一題是上台要點的建議問題。其餘題目用於實機驗收及備用問答，可以從中挑幾題顯示在對話框。

**題目不用綁死這八題，依實際模型的能力調整。** 手機上的小模型理解力和 context 長度都有限，實測後答不好的題目就拿掉或改簡單，只把答得穩的放進建議問題。模型太弱或 context 不夠時，可以這樣縮：

- 題目減到只剩「整條路線」加兩三個單一步驟的問題
- 情境資料只留每一站的事件名稱與步驟標題，不放步驟說明
- 範例從兩個減成一個，或只留輸出格式說明
- 縮小候選清單，單一步驟可先用網頁的關鍵字找出候選
- 換更大的模型後再把題目加回來

| 問題 | 期望的動作 | 期望回答的重點 |
| --- | --- | --- |
| 爸爸中風快出院了，我要申請什麼？ | 整條路線 | 先安排出院與輔具，再申請長照，之後評估身障證明 |
| 出院後輪椅去哪裡借？ | 第 1 站・借用輔具 | 輔具資源中心可以租借，可能有輔具補助 |
| 回診要怎麼去醫院？ | 第 1 站・回診交通 | 無障礙計程車、復康巴士，不確定撥 1999 |
| 長照要怎麼申請？ | 第 2 站・申請長照評估 | 撥 1966，之後會有專員到府評估 |
| 爸爸需要申請身心障礙證明嗎？ | 第 3 站・到區公所申請 | 先到區公所領鑑定表，再到醫院鑑定；是否符合由鑑定決定 |
| 我照顧爸爸好累 | 第 2 站・照顧者也要被照顧 | 喘息服務、家庭照顧者支持據點 |
| 我要結婚 | 不移動 | 目前只示範中風出院；可點婚姻與家庭大樓或撥 1999 |
| 爸爸這樣算重度嗎？ | 不移動 | 不能判斷，要由醫院鑑定；可撥 1957 福利諮詢專線 |

## 5. 架構

Vue 頁面在手機上以既有事件與步驟的名稱、同義詞查找候選。Flutter 透過 LiteRT-LM 讀取 App 私有空間的 Gemma 模型。模型只選編號，頁面驗證後用既有資料顯示說明，並交由 Three.js 帶路。建議問題已綁定三站路線，即使推論失敗，也能顯示標示清楚的「預設說明」並開始導覽。

### 5.1 網頁與 App 的訊息格式

沿用 `flutterObject`。模型和語音入口只處理 App 自己提供的離線頁面發出的主框架訊息。

| 訊息 | 送出 | 回覆 |
| --- | --- | --- |
| `llm_status` | `id` | 可用模型名稱及是否提供語音入口 |
| `llm_ask` | `id`、`question`、`choices` | `working`，接著 `done`（候選編號與實際模型名稱）或 `error` |
| `llm_cancel` | `id` | 停止使用該次回覆 |
| `city_voice` | `id` | iPhone 本機語音辨識文字或失敗原因 |
| `city_voice_cancel` | `id` | 停止收音 |

每次只跑一題。關閉對話框或等候逾時時取消請求。App 端與網頁不記錄問題、語音或回覆內容。瀏覽器預覽顯示「預設說明」，仍能操作三站導覽。

### 5.2 候選與回覆

- 自由提問先以步驟名稱與同義詞取最多四筆。完全無關或要求判斷病情、障礙程度和補助資格時，直接顯示相應說明。
- 提示詞由 App 組成。模型只處理文字，在 1,024 tokens 的上下文內從清單選編號，最多輸出 16 tokens。編號 0 表示沒有適合的候選。
- 回覆畫面用對應資料組合文字、步驟入口和既有進度。自由提問可帶到對應站點及步驟。模型不會產生網址、電話或補助資格。

### 5.3 嚮導小人

| 項目 | 規劃 |
| --- | --- |
| 模型 | Kenney [Mini Characters](https://kenney.nl/assets/mini-characters)（CC0，40 個模型）。和城市模型同一系列，風格一致 |
| 動畫 | 已確認內建 `idle`、`walk`、`emote-yes`、`interact-right`、`sit`，另有整套輪椅動畫（`wheelchair-sit`、`wheelchair-move-forward` 等） |
| 加分 | 套件附 `wheelchair-deluxe`、`aid-crutch`、`aid-cane` 等輔具模型，終點可以放一個坐輪椅的「爸爸」 |
| 大小 | 角色高約 0.7，大樓高 1.3–5；縮放約 0.35 倍 |
| 貼圖 | 和其他 Kenney 套件一樣指向 `Textures/colormap.png`，要放在自己的資料夾，例如 `public/city/characters/` |

**走路路線**：用道路中心線組成格狀路網，節點是路口，x、z 都是 −3.22、−1.05、1.05、3.22 的組合（`src/city/config.ts` 的 `PLOT_PITCH` 與外環道路）。每棟大樓在面向鏡頭那側的路上取一個「門口」點，沿道路與路口組成折線，轉彎時面向前進方向。鏡頭跟著小人移動。

**要在 `CityScene`（`src/city/scene.ts`）新增的介面**（前端實作）：

```ts
addGuide(): Promise<void>            // 載入角色，放在起點，播 idle
walkGuideTo(categoryId: string): Promise<void> // 沿路走到大樓門口，走完 resolve
guideScreenPosition(): Vector2 | null     // 對話泡泡的位置，比照 screenPosition()
```

- 現在的場景只在畫面變化時才重畫。角色走路或播動畫時要持續請求畫面，停下來就停，不然會一直耗電。
- 頭上的對話泡泡用 DOM 疊在畫面上，跟大樓標籤一樣，讀屏讀得到。
- 開啟「減少動態效果」時不播走路動畫，直接出現在目的地。

### 5.4 對話框

- **入口**：城市地圖的視角按鈕列旁加「問問城市嚮導」，點嚮導小人也會打開。
- **版面**：沿用 `BottomSheet`，地圖上方仍看得到嚮導。和類別抽屜共用同一個位置：嚮導帶路時，抽屜顯示事件步驟，上方加一列「嚮導：……　下一站 ›」。
- **內容**：對話紀錄、建議問題、文字輸入框（字級至少 16px，iPhone 才不會自動放大畫面）、送出、朗讀、模型狀態（準備中／可離線使用）。
- **語音輸入**：輸入框旁放麥克風。點小人先開對話框，使用者點麥克風後才開始收音。由 App 端做離線語音辨識，把文字填回輸入框，讓使用者確認後送出。iPhone 須先確認繁中辨識支援 `supportsOnDeviceRecognition`，並要求 `requiresOnDeviceRecognition = true`。不支援、未授權或辨識失敗時，仍可打字或點建議問題。[Apple 裝置端語音辨識說明](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition)
- **固定提醒**：「AI 回答僅供參考，內容是示範資料，請以機關公告為準；需要真人協助請撥 1999。」
- **無障礙**：新回答出現時用 `aria-live="polite"` 讀出；所有按鈕 48px 以上；不用語音也能完整操作。

## 7. 斷網 Demo

在 `microservice/` 執行 `npm run build:app`，再建置 Flutter App。App 以手機的 loopback 介面提供打包網頁，固定同一個來源以保留 WebView 進度。開發時仍可透過 `--dart-define=LIFE_EVENTS_URL=…` 指向線上預覽。iPhone 的模型檔透過 USB 傳入 App 資料容器的 `Library/Application Support/gemma-models/`，刪除 App 時會一起移除。

**上台前關閉 Wi‑Fi、開飛航模式，從重新開啟 App 開始，點建議問題走完三站。** 若要額外展示語音輸入，用同一支手機在相同條件下先確認繁中辨識。

## 8. 分工與時程

## 10. 驗收清單

- [ ] 最後放進建議問題的題目（依模型能力從第 4 節挑選、調整）都得到合理回答，候選編號正確（或備援判斷正確）
- [ ] 回答是繁體中文、100 字內，沒有出現資料以外的地點、電話、補助名稱
- [ ] 不做醫療判斷、不保證符合補助，情境以外的問題會轉介 1999
- [ ] 嚮導沿著馬路走到正確的大樓，抽屜打開正確的事件與步驟
- [ ] 「下一站」依序解鎖，進度和清單共用
- [ ] 模型載入中、推論失敗、上一題還沒答完，畫面都有清楚的狀態
- [ ] 飛航模式下，從重新開啟 App 到點建議問題、走完三站都能完成
- [ ] 若展示語音輸入，展示機在飛航模式下能把繁中語音填回輸入框
- [ ] 減少動態效果、字放大 200%、讀屏都能使用
